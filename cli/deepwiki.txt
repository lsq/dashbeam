**目前的情况**

- `engine/native`（crate 名 `sendme-native`）在 `engine/native/Cargo.toml` 中没有配置 `crate-type`，默认只产 `rlib`，不能直接生成 DLL。

**要导出为 DLL，需要做这些事**

1. 新建一个 FFI crate（或给 `sendme-native` 加 `crate-type = ["cdylib"]`），用 `cargo build --release` 产出 `.dll` + `.lib`。
2. 写 `#[no_mangle] pub extern "C"` 包装函数，例如：
   - `dashbeam_send_start(const char* const* paths, int count, const char* options_json, ProgressCallback cb, void* user_data) -> int handle`
   - `dashbeam_send_cancel(int handle)`、`dashbeam_send_free(...)` 管理生命周期。
3. `SendOptions` / `SendResult` / `FileMetadata` 是 serde 结构体，最简单的方式是跨边界传 JSON 字符串（`serde_json` 已在依赖里），避免手写 repr(C) 结构体。
4. tokio 运行时：DLL 内部持有一个全局 `tokio::runtime::Runtime`（`OnceLock`），`extern "C"` 函数里 `runtime.spawn(start_share_items(...))`，因为导出函数本身不能是 async。
5. `AppHandle`/`EventEmitter` 是 trait 抽象，可以实现一个"通过 C 函数指针回调"的版本，把进度事件 JSON 化后回调给 C++。
6. C++ 侧写一个 `.h` 头文件声明函数签名（或用 `cbindgen` 自动生成），链接生成的 `.lib`。

**注意事项**

- 字符串/内存所有权要约定清楚：推荐 DLL 返回的字符串由 C++ 调 `free` 函数释放，避免跨 CRT 边界的内存问题。
- `start_share` 已标注 deprecated，应只包装 `start_share_items`。
- 回调可能在任意 tokio worker 线程触发，C++ 侧需要自行 marshal 到 UI 线程。
- 依赖里有 `keyring`（`get_or_create_secret` 会用系统密钥环），在非桌面环境或权限受限场景要注意。

```rust
use std::ffi::{c_char, c_void, CStr, CString};
use std::net::{SocketAddrV4, SocketAddrV6};
use std::panic::{catch_unwind, AssertUnwindSafe};
use std::path::PathBuf;
use std::str::FromStr;
use std::sync::atomic::{AtomicI64, Ordering};
use std::sync::{Arc, Mutex, OnceLock};

use protocol::{
    AddrInfoOptions, AppHandle, DiscoveryModeOption, EventEmitter, FileMetadata,
    RelayModeOption, SendOptions,
};
use native::{start_share_items, SendResult};

// ---------------------------------------------------------------------------
// Globals

fn runtime() -> &'static tokio::runtime::Runtime {
    static RT: OnceLock<tokio::runtime::Runtime> = OnceLock::new();
    RT.get_or_init(|| {
        tokio::runtime::Builder::new_multi_thread()
            .enable_all()
            .build()
            .expect("dashbeam tokio runtime")
    })
}

/// Live share sessions keyed by handle. Dropping a SendResult shuts the router
/// down and auto-cleans the blobs dir, so removal == cancel.
fn sessions() -> &'static Mutex<HashMap<i64, SendResult>> {
    static S: OnceLock<Mutex<HashMap<i64, SendResult>>> = OnceLock::new();
    S.get_or_init(|| Mutex::new(HashMap::new()))
}

static NEXT_HANDLE: AtomicI64 = AtomicI64::new(1);

fn last_error_slot() -> &'static Mutex<Option<CString>> {
    static E: OnceLock<Mutex<Option<CString>>> = OnceLock::new();
    E.get_or_init(|| Mutex::new(None))
}

fn set_last_error(msg: &str) {
    if let Ok(mut slot) = last_error_slot().lock() {
        *slot = CString::new(msg).ok();
    }
}

// ---------------------------------------------------------------------------
// Options (JSON) -> protocol::SendOptions
// ---------------------------------------------------------------------------

#[derive(serde::Deserialize, Default)]
#[serde(default)]
struct FfiSendOptions {
    /// "default" | "disabled" | "custom"
    relay_mode: String,
    /// relay_mode = "custom" 时的 relay URL 列表
    relay_urls: Vec<String>,
    relay_auth_token: Option<String>,
    /// "default" | "custom"
    discovery_mode: String,
    pkarr_relay_url: Option<String>,
    dns_origin: Option<String>,
    /// "Id" | "RelayAndAddresses" | "Relay" | "Addresses"
    ticket_type: String,
    /// e.g. "0.0.0.0:0"
    ipv4_addr: Option<String>,
    ipv6_addr: Option<String>,
    /// 可选文件元数据（直接透传 protocol::FileMetadata 的 serde 形状）
    metadata: Option<FileMetadata>,
}

fn map_options(o: FfiSendOptions) -> anyhow::Result<(SendOptions, Option<FileMetadata>)> {
    let relay_mode = match o.relay_mode.as_str() {
        "" | "default" => RelayModeOption::Default,
        "disabled" => RelayModeOption::Disabled,
        "custom" => {
            let urls = o
                .relay_urls
                .iter()
                .map(|s| iroh::RelayUrl::from_str(s).map_err(|e| anyhow::anyhow!("bad relay url {s}: {e}")))
                .collect::<anyhow::Result<Vec<_>>>()?;
            RelayModeOption::Custom { urls, auth_token: o.relay_auth_token }
        }
        other => anyhow::bail!("unknown relay_mode: {other}"),
    };

    let discovery_mode = match o.discovery_mode.as_str() {
        "" | "default" => DiscoveryModeOption::Default,
        "custom" => {
            let url = o
                .pkarr_relay_url
                .as_deref()
                .ok_or_else(|| anyhow::anyhow!("custom discovery requires pkarr_relay_url"))
                .and_then(|s| url::Url::parse(s).map_err(|e| anyhow::anyhow!("bad pkarr url: {e}")))?;
            DiscoveryModeOption::Custom { pkarr_relay_url: url, dns_origin: o.dns_origin }
        }
        other => anyhow::bail!("unknown discovery_mode: {other}"),
    };

    let ticket_type = if o.ticket_type.is_empty() {
        AddrInfoOptions::Id
    } else {
        AddrInfoOptions::from_str(&o.ticket_type)
            .map_err(|e| anyhow::anyhow!("bad ticket_type: {e}"))?
    };

    let magic_ipv4_addr = o
        .ipv4_addr
        .as_deref()
        .map(SocketAddrV4::from_str)
        .transpose()
        .map_err(|e| anyhow::anyhow!("bad ipv4_addr: {e}"))?;
    let magic_ipv6_addr = o
        .ipv6_addr
        .as_deref()
        .map(SocketAddrV6::from_str)
        .transpose()
        .map_err(|e| anyhow::anyhow!("bad ipv6_addr: {e}"))?;

    Ok((
        SendOptions { relay_mode, discovery_mode, ticket_type, magic_ipv4_addr, magic_ipv6_addr },
        o.metadata,
    ))
}

// ---------------------------------------------------------------------------
// EventEmitter -> C callback
// ---------------------------------------------------------------------------

/// event/payload 字符串仅在回调执行期间有效，C++ 侧需要复制。
pub type DashbeamEventCb = extern "C" fn(*const c_char, *const c_char, *mut c_void);

struct CbEmitter {
    cb: DashbeamEventCb,
    user_data: usize, // 原始指针按值传递
}

unsafe impl Send for CbEmitter {}
unsafe impl Sync for CbEmitter {}

impl CbEmitter {
    fn fire(&self, name: &str, payload: Option<&str>) -> Result<(), String> {
        let name = CString::new(name).map_err(|e| e.to_string())?;
        let payload = match payload {
            Some(p) => CString::new(p).map_err(|e| e.to_string())?,
            None => CString::new("").map_err(|e| e.to_string())?,
        };
        (self.cb)(name.as_ptr(), payload.as_ptr(), self.user_data as *mut c_void);
        Ok(())
    }
}

impl EventEmitter for CbEmitter {
    fn emit_event(&self, event_name: &str) -> Result<(), String> {
        self.fire(event_name, None)
    }
    fn emit_event_with_payload(&self, event_name: &str, payload: &str) -> Result<(), String> {
        self.fire(event_name, Some(payload))
    }
}

/// 启动分享。立即返回句柄（>0）；分享就绪后以 "share-ready" 事件回调
/// {"ticket","hash","size","entry_type"}，失败回调 "share-error"（payload 为错误文本）。
/// options_json 可为 NULL（全默认）。返回 -1 表示参数错误，错误文本见 dashbeam_last_error。
#[no_mangle]
pub extern "C" fn dashbeam_send_start(
    paths: *const *const c_char,
    path_count: usize,
    options_json: *const c_char,
    event_cb: Option<DashbeamEventCb>,
    user_data: *mut c_void,
) -> i64 {
    let result = catch_unwind(AssertUnwindSafe(|| {
        if paths.is_null() || path_count == 0 {
            return Err(anyhow::anyhow!("paths is null or empty"));
        }
        let mut path_list = Vec::with_capacity(path_count);
        for i in 0..path_count {
            let p = unsafe { *paths.add(i) };
            if p.is_null() {
                return Err(anyhow::anyhow!("paths[{i}] is null"));
            }
            let s = unsafe { CStr::from_ptr(p) }
                .to_str()
                .map_err(|e| anyhow::anyhow!("paths[{i}] not utf-8: {e}"))?;
            path_list.push(PathBuf::from(s));
        }

        let (options, metadata) = if options_json.is_null() {
            (SendOptions::default(), None)
        } else {
            let json = unsafe { CStr::from_ptr(options_json) }
                .to_str()
                .map_err(|e| anyhow::anyhow!("options not utf-8: {e}"))?;
            let ffi_opts: FfiSendOptions = serde_json::from_str(json)
                .map_err(|e| anyhow::anyhow!("bad options json: {e}"))?;
            map_options(ffi_opts)?
        };

        let handle_id = NEXT_HANDLE.fetch_add(1, Ordering::SeqCst);

        // AppHandle: 有回调就包一层 CbEmitter，没有则为 None
        let app_handle: AppHandle = event_cb.map(|cb| {
            Arc::new(CbEmitter { cb, user_data: user_data as usize }) as Arc<dyn EventEmitter>
        });

        let cb = event_cb;
        let ud = user_data as usize;

        runtime().spawn(async move {
            let emit = |name: &str, payload: &str| {
                if let Some(cb) = cb {
                    if let (Ok(n), Ok(p)) = (CString::new(name), CString::new(payload)) {
                        cb(n.as_ptr(), p.as_ptr(), ud as *mut c_void);
                    }
                }
            };

            match start_share_items(path_list, options, &app_handle, metadata).await {
                Ok(result) => {
                    let ready = serde_json::json!({
                        "handle": handle_id,
                        "ticket": result.ticket,
                        "hash": result.hash,
                        "size": result.size,
                        "entry_type": result.entry_type,
                    });
                    emit("share-ready", &ready.to_string());
                    sessions()
                        .lock()
                        .expect("sessions poisoned")
                        .insert(handle_id, result);
                }
                Err(e) => {
                    emit("share-error", &format!("{e:#}"));
                }
            }
        });

        Ok(handle_id)
    }));

    match result {
        Ok(Ok(h)) => h,
        Ok(Err(e)) => {
            set_last_error(&format!("{e:#}"));
            -1
        }
        Err(_) => {
            set_last_error("panic in dashbeam_send_start");
            -1
        }
    }
}

/// 取消分享并释放句柄。成功返回 0，句柄不存在返回 -1。
#[no_mangle]
pub extern "C" fn dashbeam_send_stop(handle: i64) -> i32 {
    match catch_unwind(AssertUnwindSafe(|| {
        sessions().lock().expect("sessions poisoned").remove(&handle)
    })) {
        Ok(Some(_)) => 0, // drop SendResult -> router 关闭、目录清理
        Ok(None) => {
            set_last_error("unknown handle");
            -1
        }
        Err(_) => {
            set_last_error("panic in dashbeam_send_stop");
            -1
        }
    }
}

/// 已完成完整传输的对端数（share 会话内累计）。
#[no_mangle]
pub extern "C" fn dashbeam_send_completed_peers(handle: i64) -> i64 {
    catch_unwind(AssertUnwindSafe(|| {
        sessions()
            .lock()
            .expect("sessions poisoned")
            .get(&handle)
            .map(|r| r.completed_peers() as i64)
            .unwrap_or(-1)
    }))
    .unwrap_or(-1)
}

/// 返回最后一次错误的线程不安全字符串（仅在下次 FFI 调用前有效）。可为 NULL。
#[no_mangle]
pub extern "C" fn dashbeam_last_error() -> *const c_char {
    last_error_slot()
        .lock()
        .ok()
        .and_then(|s| s.as_ref().map(|c| c.as_ptr()))
        .unwrap_or(std::ptr::null())
}
```

## 注意事项

- **生命周期语义**：`dashbeam_send_start` 返回时分享还没就绪，`share-ready` 回调里才有 `ticket`（可直接给接收端用）。句柄在 `share-ready` 之后才会注册进 map —— 在 ready 前调 `dashbeam_send_stop` 可能返回 -1 但任务仍会跑完一轮启动流程。
- **`panic = "abort"`**：workspace release profile 设了 `panic = "abort"`（`engine/Cargo.toml:64`），对 cdylib 来说 panic 会直接终止宿主进程，`catch_unwind` 形同虚设。如果要给 C++ 用，建议在 profile 里改成 `panic = "unwind"`，或把该 profile 移到用 `panic="abort"` 的具体 crate（注意 workspace profile 只能定义在根）。这是一个实际风险，不是风格问题。
- **`keyring` 依赖**：`sendme-native` 依赖 `keyring`（`engine/native/Cargo.toml:30`），但在 `send.rs:42` 路径上 secret 实际走 `IROH_SECRET` 环境变量或随机生成（`types.rs:205`），不会触密钥环。
- **回调线程**：事件回调在 tokio worker 线程触发，C++ 侧不要在里面做耗时操作或假设 UI 线程。
- 我没能验证 `iroh::RelayUrl::from_str` / `AddrInfoOptions::from_str` 的确切错误类型（用了 `derive_more::FromStr`，map_err 处理成字符串即可编译），编译时如有签名出入按报错微调即可。

```cpp
// dashbeam-send: 通过 dashbeam_ffi.dll 分享文件/文件夹的命令行工具
// 用法: dashbeam-send <文件或目录> [更多路径...]
// 使用公共 iroh relay/discovery（默认），打印 ticket 供接收端使用。

#include <atomic>
#include <chrono>
#include <csignal>
#include <cstdint>
#include <cstdio>
#include <cstring>
#include <filesystem>
#include <string>
#include <thread>
#include <vector>

#ifdef _WIN32
#  include <windows.h>
#endif

#include "dashbeam.h"

namespace fs = std::filesystem;

static std::atomic<bool> g_ready{false};
static std::atomic<bool> g_failed{false};
static std::atomic<bool> g_quit{false};
static std::atomic<int64_t> g_handle{-1};
static int g_connected_peers = 0;

static void on_event(const char *event, const char *payload, void *user_data) {
    (void)user_data;
    const char *p = payload ? payload : "";

    if (std::strcmp(event, "share-ready") == 0) {
        // payload: {"handle","ticket","hash","size","entry_type"}
        std::string json(p);
        // 简单提取 ticket 字段（ticket 内不含引号/逗号）
        auto pos = json.find("\"ticket\":\"");
        if (pos != std::string::npos) {
            pos += 10;
            auto end = json.find('"', pos);
            std::string ticket = json.substr(pos, end - pos);
            std::printf("\n=== 分享已就绪 ===\n");
            std::printf("ticket: %s\n", ticket.c_str());
            std::printf("(完整回执: %s)\n\n", p);
            std::printf("等待接收端连接... Ctrl+C 停止分享\n");
        } else {
            std::printf("[share-ready] %s\n", p);
        }
        g_ready = true;
    } else if (std::strcmp(event, "share-error") == 0) {
        std::fprintf(stderr, "[share-error] %s\n", p);
        g_failed = true;
    } else if (std::strcmp(event, "share-peer-connected") == 0) {
        ++g_connected_peers;
        std::printf("[peer] 新对端连接 (累计 %d): %s\n", g_connected_peers, p);
    } else if (std::strcmp(event, "transfer-started") == 0) {
        std::printf("[transfer] 开始传输\n");
    } else if (std::strcmp(event, "transfer-progress") == 0) {
        // payload: "bytes:total:speed*1000"
        uint64_t bytes = 0, total = 0, speedx1000 = 0;
        if (std::sscanf(p, "%llu:%llu:%llu",
                        (unsigned long long *)&bytes,
                        (unsigned long long *)&total,
                        (unsigned long long *)&speedx1000) == 3) {
            double pct = total ? 100.0 * bytes / total : 0.0;
            std::printf("\r[transfer] %llu/%llu bytes (%.1f%%)  %.2f MB/s   ",
                        (unsigned long long)bytes, (unsigned long long)total,
                        pct, speedx1000 / 1000.0);
            std::fflush(stdout);
        }
    } else if (std::strcmp(event, "transfer-completed") == 0) {
        std::printf("\n[transfer] 完成: %s\n", p);
    } else if (std::strcmp(event, "transfer-failed") == 0) {
        std::printf("\n[transfer] 失败: %s\n", p);
    }
    // "active-connection-count" 等事件太吵，不打印
}

#ifdef _WIN32
static BOOL WINAPI console_ctrl(DWORD type) {
    if (type == CTRL_C_EVENT || type == CTRL_CLOSE_EVENT) {
        g_quit = true;
        return TRUE;
    }
    return FALSE;
}
#else
static void sigint_handler(int) { g_quit = true; }
#endif

int main(int argc, char **argv) {
#ifdef _WIN32
    SetConsoleOutputCP(CP_UTF8); // 保证 ticket/中文输出不乱码
    SetConsoleCtrlHandler(console_ctrl, TRUE);
#else
    std::signal(SIGINT, sigint_handler);
#endif

    if (argc < 2) {
        std::fprintf(stderr,
            "用法: %s <文件或目录> [更多路径...]\n"
            "支持同时传入多个文件和文件夹，将打包为一次分享并输出 ticket。\n",
            argv[0]);
        return 2;
    }

    // 1. 校验并收集路径（文件或目录均可，与 GUI 的 start_share_items 一致）
    std::vector<std::string> storage;
    std::vector<const char *> paths;
    for (int i = 1; i < argc; ++i) {
        std::error_code ec;
        fs::path p = fs::absolute(argv[i], ec);
        if (ec || !fs::exists(p, ec)) {
            std::fprintf(stderr, "路径不存在: %s\n", argv[i]);
            return 2;
        }
        storage.push_back(p.string());
        paths.push_back(storage.back().c_str());
        std::printf("添加: %s\n", storage.back().c_str());
    }

    // 2. 启动分享。options_json=nullptr -> 公共 iroh relay + n0 discovery + Id ticket
    int64_t h = dashbeam_send_start(paths.data(), paths.size(),
                                    nullptr, on_event, nullptr);
    if (h < 0) {
        const char *err = dashbeam_last_error();
        std::fprintf(stderr, "启动分享失败: %s\n", err ? err : "unknown");
        return 1;
    }
    g_handle = h;
    std::printf("正在上线（公共 iroh relay）...\n");

    // 3. 等待 share-ready / share-error（首次建 relay 连接可能需要十几秒）
    for (int i = 0; i < 600 && !g_ready && !g_failed && !g_quit; ++i)
        std::this_thread::sleep_for(std::chrono::milliseconds(100));

    if (g_failed) { dashbeam_send_stop(h); return 1; }
    if (!g_ready) {
        std::fprintf(stderr, "%s\n", g_quit ? "已取消" : "等待 share-ready 超时");
        dashbeam_send_stop(h);
        return 1;
    }

    // 4. 保持分享会话存活，直到 Ctrl+C
    while (!g_quit)
        std::this_thread::sleep_for(std::chrono::milliseconds(200));

    std::printf("\n正在停止分享...\n");
    if (dashbeam_send_stop(h) != 0) {
        const char *err = dashbeam_last_error();
        std::fprintf(stderr, "停止失败: %s\n", err ? err : "unknown");
        return 1;
    }
    std::printf("已停止。\n");
    return 0;
}
```

2. **接收端**：`receive.rs:42` —— 只有当 ticket 里 `relay_urls` 和 `ip_addrs` 都为空时才启用 DNS 查询；`fetch_metadata` 走的是 `receive.rs:286-304` 同样的逻辑。你的 Id ticket 正好落进这条路径。
3. DNS 查询返回空 → `endpoint.connect` 直接失败 → `Connection failed: No addressing information available`。

## 最可靠的修复：改用 `RelayAndAddresses` ticket

让寻址信息直接内嵌在 ticket 里，接收端完全不需要 DNS 解析：

```cpp
// 原: dashbeam_send_start(paths, n, nullptr, on_event, nullptr);
const char *opts = R"({"ticket_type":"RelayAndAddresses"})";
int64_t h = dashbeam_send_start(paths.data(), paths.size(),
                                opts, on_event, nullptr);
```

这样 ticket 自带 sender 的 home relay URL（和直连地址），`receive.rs:42` 的判断不成立，接收端直接连 relay，不依赖 pkarr/DNS 传播。代价是 ticket 更长、会泄露 relay/地址信息（对 CLI 场景无所谓）。

注意：`RelayAndAddresses`/`Relay` 需要 endpoint 已连上 home relay 才有意义。我没能完全确认 `run_share_session`（`engine/protocol/src/send.rs`）是否在生成 ticket 前等待 relay 上线 —— 如果 ticket 里没有 relay URL，可以让 CLI 在 `share-ready` 后稍等再用，或检查 `SendResult` 构造处的等待逻辑。

## 如果必须继续用 `Id` ticket

- 在 CLI 收到 `share-ready` 后**延迟几秒**再把 ticket 给接收端，等 pkarr 发布传播（n0 DNS 有 TTL，接收端首次解析还可能被 DNS 缓存坑到）。
- 确认接收端 `discovery_mode` 也是 `Default`——如果 GUI/接收方配置了自定义 pkarr relay，它不会去查 n0 DNS，永远解析不到。
- 确认接收端所在网络能解析 `dns.iroh.link` 的 TXT 记录（企业 DNS/防火墙可能拦掉；n0 DNS 依赖标准 DNS TXT 查询）。
- 确认发送端 `relay_mode` 不是 `disabled` —— 纯直连场景下发布的地址仍应可被解析，但如果发送端完全离线则无解。

建议：CLI 直接默认用 `RelayAndAddresses`，把 `Id` 留给需要短码的场景。

## 1. 引擎侧：`SpeedMeter` 滑动窗口测速

`engine/protocol/src/progress.rs` 定义了共享的进度统计逻辑：

- `SpeedMeter` 是一个**滑动窗口**测速器（默认窗口 `SPEED_WINDOW_SECS = 3.0` 秒），维护 `(时间, 累计字节数)` 样本队列。累计平均值会被慢启动拖垮、也不会在停顿时回落，所以改用窗口。 dashbeam:44-57

- 速度只统计**用户 payload 字节**：`split_child_sizes` 把 hash-seq root 和集合元数据从计数字节中剔除（`FIRST_PAYLOAD_BLOB_INDEX = 2`），保证显示的速度反映实际文件传输而非协议开销。 dashbeam:8-31 

## 2. 事件节流与线格式

- 进度事件最多每 `PROGRESS_MIN_BYTES = 1MB` 或每 `PROGRESS_MIN_SECS = 0.2s` 发一次（先到为准）。 dashbeam:18-22

- 速度从整数除以 1000 还原，`Math.max(..., 0)` 把负值钳为 0。 dashbeam:47-49

```rust
    pub fn record(&mut self, at_secs: f64, cumulative_bytes: u64) {
        self.samples.push_back((at_secs, cumulative_bytes));
        let cutoff = at_secs - self.window_secs;
        while self.samples.len() > 1 {
            let Some(&(front_secs, _)) = self.samples.front() else {
                break;
            };
            if front_secs >= cutoff {
                break;
            }
            self.samples.pop_front();
        }
    }
```

```rust
    pub fn bytes_per_sec_at(&self, now_secs: f64) -> f64 {
        let (Some(&(oldest_secs, oldest_bytes)), Some(&(newest_secs, newest_bytes))) =
            (self.samples.front(), self.samples.back())
        else {
            return 0.0;
        };

        let elapsed = now_secs.max(newest_secs) - oldest_secs;
        if elapsed < MIN_WINDOW_SECS {
            return 0.0;
        }
        newest_bytes.saturating_sub(oldest_bytes) as f64 / elapsed
    }
```

## 具体机制

### 1. 发送侧：每个文件一个 blob

`import_paths`（`engine/native/src/import.rs`）把每个文件单独导入 blob store（`BlobFormat::Raw`），得到一个 `(文件名, hash)` 列表；然后构造一个 `Collection`（文件名 → blob hash 的映射）并把它本身也存为 blob。 dashbeam:20-24 dashbeam:85-92 

集合再挂到一条 **HashSeq**（按顺序列出所有子 blob 哈希的清单）下，ticket 里只带这一个根哈希（`BlobFormat::HashSeq`）。所以**每个分享（哪怕单文件）都是一个 collection**：blob 0 是 hash-seq root，blob 1 是集合元数据，从 index 2 开始才是真正的文件 payload。 dashbeam:216-216 dashbeam:8-10 

```mermaid
flowchart TD
    Ticket["Ticket → HashSeq root hash"] --> HS["HashSeq (blob 0)<br/>子 blob 哈希列表"]
    HS --> Meta["Collection metadata (blob 1)<br/>文件名→哈希映射"]
    HS --> F1["file1 (blob 2)"]
    HS --> F2["file2 (blob 3)"]
    HS --> F3["file3 (blob 4)"]
```

### 2. 传输方式：一条连接、一个 get 请求，按序拉取全部子 blob

接收侧（`engine/protocol/src/receive.rs`）先下载 hash-seq 和 `sizes` 向量算出总 payload，然后用 `db.remote().execute_get(connection, local.missing())` 发起**一次** get 请求，流式按序取回所有缺失的子 blob —— 所有文件复用同一条 QUIC 连接（QUIC 多路复用、共享拥塞控制），而不是每个文件建一条连接。 dashbeam:155-177 

因此从进度角度看它是"一个传输"：进度条的总字节是所有文件之和，速度跨文件连续统计；但落盘时每个 blob 按集合里的文件名还原成独立文件，绝不是接收方拿到一个拼起来的大文件。

### 3. 这么做的收益

- **粒度级断点续传**：`local.missing()` 只请求缺失的 blob/分块。传了 3 个大文件断掉后重连，已完成的文件直接跳过（`local.is_complete()` 时甚至不连），只补缺口。 dashbeam:134-135 dashbeam:224-231 
- **独立校验**：每个 blob 由自己的 BLAKE3 哈希寻址，逐块校验，单文件损坏不会污染其他文件。
- **广播**：`completed_peers` 计数表明同一个 collection 可同时服务多个接收者，每个 peer 只拉自己缺的部分。 dashbeam:167-170 

### 与"打包"的对比

唯一接近"打包"的是集合元数据本身（文件名列表），它只是几十字节的描述符。对超大文件，iroh-blobs 内部还会把单个大 blob 按 chunk 切分校验/续传，但逻辑上仍是**逐文件传输**，不是 tar 式合并。

## 现状

### 引擎内部其实知道每个 blob（文件）的进度

`send.rs` 的 `SessionProgress.ledger`（`ShareProgress`）按 `(connection_id, request_id)` + blob index 记账：

- `RequestUpdate::Started` 时调用 `session.ledger.blob_started(key, m.index, m.size)` —— 拿到了**当前在传哪个 blob（`m.index`）及其大小**。 dashbeam:439-457 
- `RequestUpdate::Progress` 时调用 `session.ledger.blob_progress(key, m.end_offset)` —— 拿到该 blob 的字节偏移。 dashbeam:458-483 

由于 collection 里 blob index 与文件一一对应（index ≥ 2 为 payload 文件，顺序即 collection 中的文件顺序），引擎**具备推导"正在传第几个文件、该文件传了多少"所需的全部信息**。 dashbeam:8-10 

### 但发出的事件只有聚合值

`emit_session_progress` 把 ledger snapshot 聚合成 `bytes:total:speed` 三字段发出，payload 里**不含 blob index 或文件名**。 dashbeam:334-342 dashbeam:291-294 

前端 `transfer-progress` 事件的 schema 也只有 `bytesTransferred / totalBytes / speedBps / etaSeconds`，UI 只能显示总进度条。 dashbeam:47-53 

## 如果要支持逐文件进度

改动是可行的，因为数据都在：

1. `emit_session_progress` 在发事件时从 ledger 取出当前活跃 blob 的 `index` 和 `end_offset`，把 `index → 文件名` 映射（发送侧有 collection）连同该文件已传字节一起塞进 payload；
2. `parseProgressPayload` 扩展字段解析；
3. UI 增加当前文件名 + 文件序号（"第 3/7 个文件"）或逐文件进度条。

注意两点复杂性：blob 的请求顺序不一定严格串行（接收端按 `missing()` 范围拉取，多个请求可交错），以及广播场景下多个 peer 同时拉不同文件时"当前文件"不唯一——展示上需要选定某个 peer 或取聚合口径。这两点我未在代码中验证现有处理，属于设计时需要确认的地方。
